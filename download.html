下载 ​

VimAct 通过本网站分发 APK。下载入口在本页，APK 文件和校验值放在站点仓库的 Releases 里。

系统要求：Android 10（API 29）及以上，配一把物理键盘。APK 按 CPU 架构分开出，一个渠道三枚，装哪一枚看机器的架构；拿不准就装 universal 那枚，arm64-v8a、armeabi-v7a、x86、x86_64 四套都在包里。原生库只有一个，是 AndroidX 图形库顺着 Compose 的依赖链带进来的 libandroidx.graphics.path.so，每个架构一份、单份不到 11 KB；本项目自己不含原生代码。

两个渠道 ​

渠道版本名形式定位发布条件
正式版0.1.0日常可用最高级别混淆 + 正式签名 + 真机验证通过
测试版0.2.0-beta、0.2.0-beta.2提前尝新，随时可能坏最高级别混淆，不等真机验证结论

没有第三条渠道。debug 构建是开发机上联调用的，混淆关闭、用调试签名，不具备发布条件，也不会出现在下载页上。

真机验证只管正式版。正式签名两条渠道都想要，可那把钥匙还没配出来，所以当前这轮测试版由一把试签密钥签发，下一节把这个破例写在明处。装了这轮测试版的人，将来换正式签名那枚会被系统以 INSTALL_FAILED_UPDATE_INCOMPATIBLE 拒掉，要先卸载，无障碍开关和应用里的排除列表跟着没。

同一个渠道的三枚包共用一个 versionCode，能不能装上只看架构对不对。架构不对，系统报 INSTALL_FAILED_NO_MATCHING_ABIS，界面上通常写着「与设备不兼容」，不会装成半好。版本名一样而 versionCode 更小那种情况是另一回事：装进更小的 versionCode 得先卸载再装。

版本号按语义化版本走，MAJOR.MINOR.PATCH，当前处于 0.x 阶段。版本名写在 app/build.gradle.kts 的 baseVersionName 里，测试版的 -beta 后缀由 beta 构建类型自动追加；同一轮迭代里出第二个、第三个测试版，后缀带序号 -beta.2、-beta.3，序号取 tag 尾巴上那个数。发下一轮时改 baseVersionName 这一行，并把 versionCode 抬上去，两处都还是手工。文件名格式 vimact-<版本名>-<渠道>-<架构>.apk，架构位取 arm64-v8a、armeabi-v7a 或 universal，装错哪一枚一眼能看出来。

当前状态 ​

测试版出包了：0.1.0-mvp-beta，2026-10-30 发在站点仓库的 Releases，标记为 pre-release。三枚都是最高级别混淆的产物（R8 full mode、类打平到默认包、方法名激进重载、资源压缩、不保留行号与源文件名，两条渠道共用同一份混淆配置），逐包过完十一条静态体检与验签，同一把试签密钥（证书 SHA-256 开头 6d9cc0f4）签发。正式版还没有构建。

判断架构只有一条硬依据：连上手机跑 adb shell getprop ro.product.cpu.abi，回什么就装什么。不想连 adb 就装通用包，多花 50,073 字节换一次不用判断。

发布脚本挡在几条硬门槛上，任何一条不合就退出，远端什么都不会动：三枚产物要取齐、版本名要一致且等于 tag、混淆后的静态体检十一条逐包全过、包必须签名且只允许一个签名者、三枚的证书必须是同一把、也不能带 debuggable 标记。正式版另外要写明真机验证已经跑过，并且指纹要就是仓库里登记的那把正式指纹。这一轮测试版跳过的只有最后那半句比对，其余照常执行。

剩下的一件事在人身上：一把正式签名密钥。装机跑通完整闭环仍然是正式版的前提，这轮测试版没有等它，装出问题请在 Releases 里回话。

完整性校验 ​

每个 APK 旁边都提供 SHA-256，列在对应 Release 的正文里。下载后核对：

sha256sum vimact-<版本名>-<渠道>-<架构>.apk

对不上就不要装。

权限清单 ​

APK 不声明 INTERNET。整份清单上只有一条：com.vimact.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION，AndroidX 合并 manifest 时自动加上的，由本应用自己定义，protectionLevel 是 signature，同签名的应用才请求得到，跟系统敏感权限无关。装机时系统弹出的权限请求仍然是空。

它能读屏幕和派发点击，全部来自你在系统设置里手动授予的无障碍服务，撤销随时生效。不申请录屏权限，不申请存储权限，不含第三方分析 SDK。

安装 ​

拿到 APK 后用文件管理器打开安装，允许一次「来自此来源的应用」。装完必须去开无障碍服务，否则一切都不会发生，步骤见启用无障碍服务。

关于自行构建 ​

源码当前未公开，自行构建复现这条路暂时走不通。开放计划写在首个正式版的发布说明里。
