常见问题 ​

按 F 打不出字母 f 了 ​

hint 模式内 F 是退出键，会吃掉。要连续打 f 的场景（写代码、聊天）不该在 hint 模式里：按 Esc 出来。

输入法弹出的时候不用担心这件事，VimAct 那时把按键完全交回 IME，f 正常上屏。

装了、开了服务、按 F 没反应 ​

按这个顺序排查：

  1. VimAct 主界面状态行是不是 Status: enabled。
  2. 当前 App 有没有被加进排除列表。
  3. 输入法是不是正弹着。
  4. ROM 的省电策略有没有把应用冻结，见各家 ROM 的额外坑。

四条都排除了还没反应，属于 OEM 的 onKeyEvent 兼容性问题。这是 v0.1 明确的风险项，把机型和 ROM 版本记下来。

有些控件没有标签 ​

三种原因。

自绘控件：游戏画面、SurfaceView、部分图表，开发者没暴露无障碍节点，谁都看不见它。

上限有两道。一次扫描最多收 400 个目标；能贴出多少标签另算，封顶是当前字符集的平方。默认字符集 16 个字母，最多 256 个标签，多出来的目标拿不到标签。

WebView：按浏览器暴露给无障碍树的网页结构处理，长页面或自定义滚动容器会打折。

标签为什么突然整套变了 ​

为了保持「没有任何标签是另一个标签的前缀」，重排有时候比局部修补更省事，此时整套重新分配一次。表现是滚动一下屏幕，所有标签集体变一次。

长列表怎么往下滚 ​

分两种情况。

光标模式（没进 hint 模式）下随便滚：VimAct 只吃方向键、点击键、通知键和触发键，PageUp/PageDown、方向箭头这些照旧交给前台应用，列表该怎么动还怎么动。滚完按方向键，光标会重新吸附到最近的候选上。

hint 模式里滚不动。这是模态，所有按键都被吃掉，PageDown 也不例外——它不会写进输入缓冲，却也传不到前台应用。正确节奏是 Esc 退出、滚一页、再按 F 重来——重扫时标签按节点身份保留，原来标 b 的大概率还是 b。

和 Key Mapper 会不会打架 ​

非 hint 模式下 VimAct 只接手自己那几个键：方向键、光标点击键、通知键和触发键，其余一律放行。这求的是共存，不是集成。

需要留意的是键位撞车：如果 Key Mapper 也把 F 或 Space 映射了别的动作，两边都会想拦。建议把 VimAct 的通知键或光标点击键（见设置）挪开，或者在 Key Mapper 侧避开这几个键。

会不会读到我的密码 ​

无障碍服务能读到的东西由系统决定：节点类名、viewId、文本、contentDescription、边界坐标。它拿不到屏幕像素，那需要录屏权限，VimAct 没申请。

密码类输入框在系统层默认不会把明文文本回传给无障碍节点。而且输入框一旦激活、输入法弹出，VimAct 立刻收起全部标签和光标，完全不碰按键。

至于读取范围本身：APK 没有 INTERNET 权限，装机的权限清单上可以直接看到。数据没有出口。

费电吗 ​

那个 32 毫秒的重扫循环只在两种情况下跑：hint 模式开着，或者光标还活着。空闲时它一次也不执行，只等系统事件。通知角标走另一条路：SystemUI 发事件才去查通知行，两次查询间隔不少于 16 毫秒，角标出现和消失各用 140 毫秒淡入淡出。

需要 root 或者跑 ADB 命令吗 ​

都不需要。第一次设置只有安装 APK 和打开无障碍服务开关两步。网上有些同类工具的教程要求你常驻 adb shell 或执行 input tap，VimAct 走的是 dispatchGesture，那条路不需要 shell。

分屏、画中画、折叠屏外屏 ​

折叠屏和平板的物理键盘场景是主要目标之一，常规使用没问题。分屏、多窗口、画中画下只依赖活动窗口的根节点，行为不做保证。

源码在哪能看到 ​

目前不开源，页面上也没有 GitHub 按钮。首个正式版发布时一并说明源码计划。
