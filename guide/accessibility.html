启用无障碍服务 ​

VimAct 读屏幕上的控件树、拦按键、派发点击，这三件事全部走 Android 的无障碍服务（AccessibilityService）。零 root 也来自它。

为什么必须是它 ​

要在别的 App 里完成「查看 → 定位 → 点击」，需要三件事，而整个公开 API 里同时提供这三件事的只有无障碍服务：

需要的能力对应配置没有它会怎样
读到当前屏幕的控件树和坐标canRetrieveWindowContent不知道该把标签画在哪里
拦下按键事件，自己处理canRequestFilterKeyEventsF 只会打字，永远进不了 hint 模式
派发一次点击canPerformGestures有些控件的 ACTION_CLICK 失败时无路可走

覆盖层走的是 TYPE_ACCESSIBILITY_OVERLAY。这个类型由无障碍服务自身授权，所以不需要 MediaProjection 录屏权限，也不会看到那个「正在录屏」的系统提示。

打开 ​

  1. 系统设置 → 无障碍 →（不同 ROM 名称略有差异）已下载的应用 / 已安装的服务。
  2. 列表里选 VimAct。
  3. 打开开关，系统会弹出「允许此服务读取所有窗口内容」之类的授权确认，同意。

从 VimAct 主页点「Open accessibility settings」会直接打开系统的无障碍设置页，省掉第 1 步的找路。列表还在，VimAct 还是要自己选中、开关还是要自己打开。

关掉开关，VimAct 立刻完全失效：不读屏幕、不贴标签、不碰按键。它没有任何后台常驻的意义。

各家 ROM 的额外坑 ​

无障碍服务在国产 ROM 上属于容易被回收的进程，以下几种情况会导致「装了、开了、但按 F 没反应」：

  • 省电策略把应用冻结。需要在电池设置里给 VimAct 放行「无限制」或允许后台运行。
  • 「清理加速」类功能一键杀掉了服务。重新打开开关即可，但要意识到它会反复发生。
  • 部分机型要求「自启动」权限，否则系统重启后服务不会自动恢复。

这类问题属于 OEM 兼容性，是 v0.1 明确列出的风险项。遇到时先按上面三条排查，再考虑常见问题里的其他原因。

它能看到什么 ​

无障碍服务能读到当前窗口的控件树：节点类名、viewId、文本、contentDescription、边界坐标。VimAct 拿这些内容判定哪些节点可点击，并把标签画在正确的位置。

它读不到屏幕像素（那需要录屏权限），也读不到其他应用的私有数据。密码输入框一类的内容本身就不会以明文出现在节点文本里。

这些读取全部发生在内存中，用完即丢。APK 不申请 INTERNET 权限，也就是说它没有把任何东西送出去的通道。这一点可以直接从安装时的权限清单核验。
